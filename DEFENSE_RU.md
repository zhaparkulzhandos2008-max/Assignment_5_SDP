# Подготовка к защите Assignment 5

## Что делает проект

Есть восемь готовых вариантов пути от склада до больницы. Программа выбирает один из них. Она не строит дорогу на карте. Один алгоритм выбирает самый быстрый путь, другой — самый дешёвый, третий — экологичный, четвёртый учитывает несколько показателей, пятый выбирает минимальную дистанцию.

## Как работает Strategy

`RouteStrategy` — общий договор для алгоритмов. `RoutePlanner` — Context, который хранит выбранную стратегию. Вызов `planner.plan(routes, request)` передаёт работу стратегии. Через `setStrategy(...)` можно заменить алгоритм, сохранив тот же объект planner.

Пример: `planner.setStrategy(new FastestRouteStrategy());` — дальше planner выбирает по времени. Затем `planner.setStrategy(new CheapestRouteStrategy());` — тот же planner выбирает по стоимости.

## Порядок выбора

Сначала отбрасываются недопустимые маршруты: закрытые, запрещённые для заявки, дороже бюджета, дольше срока или выше лимита выбросов. После этого стратегия оценивает оставшиеся пути. При одинаковой оценке побеждает меньший ID по алфавиту. Если ничего не осталось, выбрасывается понятное исключение, а не возвращается null.

`ScoredRouteStrategy` содержит общие шаги. Конкретный класс определяет `score` и `explain`. Между planner и алгоритмами применяется Strategy; внутри общего базового класса дополнительно используется Template Method.

## Что объяснить про формулы

Время — это базовое время плюс пробки и погода. Цена — базовая стоимость плюс километры, умноженные на тариф, плюс сборы. Для срочного заказа добавляется 1000 тенге. Ограничения проверяют именно итоговые значения.

Экологическая оценка по умолчанию: CO2 * 0.9 + расстояние * 0.1. Это условная бизнес-модель, а не научный расчёт выбросов. Она находится в EcoFriendlyRouteStrategy, потому что отражает цель этого алгоритма.

Balanced приводит каждый показатель к диапазону от 0 до 1: `(значение - минимум) / (максимум - минимум)`. Это позволяет складывать время, цену, расстояние и CO2 с весами. Нормализация считается только по допустимым маршрутам. Если все значения одинаковы, вклад показателя равен нулю. Веса неотрицательные и в сумме дают 1. Чем меньше итоговая оценка, тем лучше.

## Кто выбирает саму стратегию

`StrategySelector` использует список правил. Первое совпавшее правило побеждает. Срочный заказ получает Fastest даже при ecoPreferred. Иначе ECO или ecoPreferred выбирает Eco, ECONOMY — Cheapest, STANDARD — Balanced. Selector решает, какой алгоритм взять, а Strategy — как выбрать маршрут.

## Ответы про SOLID и Bridge

SRP: planner, selector, ограничения и алгоритмы отвечают за разные задачи. OCP: новый алгоритм добавляется новым классом и регистрацией без изменения planner. DIP: planner зависит от интерфейса, а не конкретного алгоритма.

Strategy меняет поведение — способ выбора маршрута. Bridge разделяет две независимо развивающиеся иерархии: абстракции и реализации. В этом проекте нет такой пары иерархий.

## Возможные изменения на защите

Измени веса Balanced на `(0,1,0,0)` — он будет минимизировать стоимость. Добавь новое правило Selector перед общим STANDARD. Создай стратегию по образцу DistanceFirstStrategy, затем зарегистрируй её в Main. Не добавляй ветки по названиям стратегий в RoutePlanner.

## Ограничения решения

Данные демонстрационные. Нет API карт, интерфейса и сохранения заказов. Все входные пути должны относиться к одной паре точек. Balanced повторно вычисляет минимумы и максимумы: для больших списков нужен расчёт один раз на заявку. Для реальных денежных расчётов лучше BigDecimal. README содержит подробную архитектуру и проверенные результаты.
